周末用 Claude Code 处理了 677 张历史截图和旧电脑屏幕翻拍照片，整理出 40 多份独立文档。

我有个坏习惯：看到有用的东西随手截张图，或者退旧电脑前对着屏幕一通狂拍，拍完就扔在文件夹里不管了。删了怕丢信息，留着又根本不会去翻。这次干脆让 CC 试着一次性归档，效果出奇的好。

## 怎么做的

原始图片每张 2 到 4 MB，Claude 的 Read 工具单文件上限是 256 KB，直接读会报错。解决办法是用 macOS 自带的 `sips` 命令批量缩成 1000px 长边的 JPEG，每张压到 100 到 200 KB，Claude 就能直接看图了。

整个过程没用传统 OCR，直接靠 Claude 自己的多模态视觉能力。最大的好处是它看得懂上下文：扫一眼窗口标题栏的文件名，就知道当前拍的是哪份文档；遇到 Word 截图，能自动把正文和侧边的修订批注框区分开。这些都是传统 OCR 最头疼的地方。

执行时开了 6 个 agent 按图片编号分段并行跑，有些 agent 自己又派生出子 agent，前后一共跑了 30 多个 agent。最后从这堆图里捞出来 27 篇头马演讲稿（完整转录英文原文）、16 篇技术文档（提炼目录和关键内容），外加 10 段早年的日记。

## 一图胜千言

跑完之后好奇这波烧了多少 token，让 CC 自己算了笔账。

Claude 算图片 token 不看文件体积，只按像素面积换算：**tokens = (width × height) / 750**。

这批截图缩到 1000px 长边后，横屏大约是 1000 × 750 像素，套进公式算下来，刚好**每张图约 1000 token**。

一图胜千言，诚不我欺。

677 张图加起来差不多 67.7 万 input token。按 Opus 4.6 的 API 价格（$5 / 百万 input token），光读图本身只合 3.4 美元；算上 30 多个 agent 的上下文开销和长篇输出，整趟活如果走 API 大概在 20 到 30 美元之间（约 175 元人民币）。放在 Max 订阅额度里跑，相当划算。
